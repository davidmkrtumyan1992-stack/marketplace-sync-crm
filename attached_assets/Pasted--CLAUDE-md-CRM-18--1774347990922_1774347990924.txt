ШАГ 5 — Исправить проблему:

На основе найденной причины исправить логику cleanup.

Если причина (a) — resolvedStoreId = null:
Добавить fallback cleanup по organizationId:

// Закрывать поставки по orgId если storeId неизвестен:
if (activeSupplyIds !== null && activeSupplyIds.size === 0) {
  // WB вернул пустой список — закрыть все open поставки этой орг:
  await db.execute(sql`
    UPDATE wb_supplies
    SET status = 'closed', closed_at = NOW()
    WHERE status = 'open'
    AND organization_id = ${orgId}
  `);
  console.log('[wb-supply-sync] Закрыто все open поставки — WB вернул 0 активных');
}

// Если WB вернул поставки — закрыть только отсутствующие:
if (activeSupplyIds !== null && activeSupplyIds.size > 0) {
  const openRows = await db.execute(sql`
    SELECT supply_id FROM wb_supplies
    WHERE status = 'open'
    AND organization_id = ${orgId}
  `);
  const openSupplies = (openRows as any).rows || openRows;
  const toClose = openSupplies
    .map((r: any) => r.supply_id)
    .filter((id: string) => !activeSupplyIds!.has(id));
  for (const supplyId of toClose) {
    await db.execute(sql`
      UPDATE wb_supplies
      SET status = 'closed', closed_at = NOW()
      WHERE supply_id = ${supplyId}
      AND organization_id = ${orgId}
    `);
  }
  console.log(`[wb-supply-sync] Закрыто устаревших: ${toClose.length}`);
}

Если причина (b) — формат supply_id не совпадает:
Нормализовать supply_id при сравнении — убрать префикс WB-GI-
или добавить его при необходимости.

ШАГ 7 — Исправить нестабильность отображения:

Нестабильность («поставки то появляются то исчезают») —
это признак конфликта между кэшем React Query и автосинком.

В WildberriesOrders.tsx найди useQuery для поставок
(GET /api/wb/supplies).
Убедись что refetchInterval установлен:
- refetchInterval: 120000 (2 минуты) — синхронно с автосинком
- staleTime: 0 — всегда считать данные устаревшими
- refetchOnWindowFocus: true — обновлять при фокусе окна

Если эти параметры не установлены — добавить.
